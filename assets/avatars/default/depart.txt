# depart: a worker has been sent off. A bud swells on the left shoulder,
# pinches off into a child slime, and drifts up and out past the top-left
# corner; the parent watches it go. 14 fps, loop=false, 1.0 s.
#
# Everything is in the base layer and nothing is in @overlay, which is the
# opposite of what the sprite accessories do and is deliberate. The overlay
# exists so an accessory never destroys the body art underneath it; the child
# never passes over the body -- it lives in the empty corridor above the left
# shoulder, x0-x3 of rows 0-2, which the resting drawings leave clear -- so
# there is nothing to protect, and one drawing per frame is easier to read in
# a diff than two.
#
# It leaves by the upper *left* on purpose. The right of the grid is where
# every accessory hangs (the thought bubble, the zZz, the mute cross), so a
# child going that way would walk into whichever one comes back up when the
# clip ends; and wake_slide already made the left the road the slime arrives
# by. Things come and go from the left here.
#
# The child leaves the 16x16 grid, not the band: a cell outside the grid is
# simply not drawn, which is what makes leaving free. With no accessory up
# the body is centred in a 22-cell stage, so the child winks out about three
# cells short of the band's own edge -- at 16 px a cell that is a shrinking
# blob at the corner, which is the read that matters.
#
# The last frame is idle.txt's first frame, cell for cell. Same contract the
# two entrances keep: a one-shot holds its last drawing until the policy asks
# for another clip, so ending anywhere else would leave the slime resting in
# a pose the breathe does not start from.
